ONE-TIME SETUP

Connect your editing space.

You’ll keep your Vercel website and use /admin to edit it. Supabase stores the content, verifies your login, and holds uploaded PDFs.

  1. Create a Supabase project. Go to supabase.com/dashboard ↗, create a project, choose a nearby region, and keep its database password private. A database password is different from your admin login.
  2. Set up the tables and upload rules. Open the project’s SQL Editor. Download setup.sql, copy its contents into a new query, and run it once.
  3. Create your admin login. Under Authentication → Users, use Add user / Create user. Enter your email and a strong password and enable automatic email confirmation for this manually created account. Copy the new user’s UUID. Turn off public sign-ups in the Auth settings: this site only needs your admin account.
  4. Give only that account editing permission. In SQL Editor, replace the UUID below with the one you copied, then run the query.
    insert into public.portfolio_admins(user_id)
values ('YOUR-USER-UUID-HERE');
  5. Connect the website. Find the project URL and publishable key in the project’s Connect / API settings. A legacy anon key is also supported. Go back to /admin, open “Connect my Supabase project,” and enter those two public values. Download the generated config.js. Never use a secret or service-role key.
  6. Update GitHub once. Replace assets/js/config.js in your portofolio repository with the downloaded file and commit/push it. Vercel redeploys automatically. Do not put your admin password or database password in GitHub.
  7. Sign in and publish. Open your website’s /admin page, log in with the admin email/password you created, and make an edit. Save the form, then Publish changes. That first publish copies the bundled site content into your database. Future edits don’t require GitHub changes.
How uploads, analytics, and backups work
  • PDF uploads are limited to 5 MB. A new file gets a new URL; earlier uploads remain in the storage bucket so they can still be restored from a backup. You can manage old files in Supabase Storage.
  • The public website falls back to its bundled content when the database is unavailable. Download a content backup after major changes; update data/content.json in GitHub occasionally if you want the fallback to include those changes.
  • Analytics starts only after connection. Page views, browser sessions, project opens, project-link clicks, and CV-button clicks are counted. A session is not necessarily a unique visitor, and a CV click does not prove a completed download.
  • Analytics stores an anonymous session identifier, event name, target, and time. It does not store visitor email addresses or IP addresses in the analytics table. Counts are approximate and cannot be reconstructed for traffic before setup.
  • Public visitors cannot read the analytics table or edit content. Only the allowlisted admin UUID can publish or upload files. There is no default admin password.
  • If you forget your admin password, manage the user under Supabase Authentication. This version uses email/password login and does not offer public account registration.

Until this setup is complete, /admin offers an explicitly marked preview. Preview edits never update the live website.
